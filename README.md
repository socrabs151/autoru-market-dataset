# autoru-market-dataset

Сборщик объявлений [auto.ru](https://auto.ru/) для личного датасета и анализа
рынка подержанных автомобилей. Извлекает характеристики и цены объявлений по
заданным фильтрам, накапливает ежедневные снимки и формирует историю изменений.

**Состояние проекта.** Этапы 1–4 завершены. Реализованы сбор по фильтрам,
обеспечение полноты выборки, история цен, выгрузка данных, экран в терминале и
HTTP-сервис для внешней системы управления парсерами. Персональные данные
продавцов не собираются и не сохраняются.

## Назначение

Проект решает одну задачу: получить воспроизводимую таблицу объявлений с
историей изменений цен. Всё остальное подчинено ей.

| Возможность | Реализация |
| --- | --- |
| Сбор объявлений по фильтрам | марка, модель, год, цена до, регион, кузов, привод, коробка, двигатель, цвет, число мест, происхождение марки, наличие |
| Представление данных | плоские таблицы: цена, пробег, год, марка, модель, кузов, двигатель, коробка, привод, цвет, число фотографий, тип продавца, регион, состояние документов |
| Накопление истории | ежедневные снимки; запись создаётся только при фактическом изменении данных объявления |
| Исключение персональных данных | имя продавца, телефон, адрес, название автосалона и город не собираются |
| Интерфейсы | командная строка, экран в терминале, HTTP-сервис |

## Поддерживаемые фильтры

Фильтры разделены на две группы. Разделение обусловлено возможностями сайта и
влияет на способ обработки.

**Фильтры, применяемые на стороне сайта.** Включаются в адрес запроса как
составляющие пути. Для перечисленных ниже справочников допустимые значения
задаются в коде и проверяются перед сбором:

| Фильтр | Пример |
| --- | --- |
| Регион или город | `/moskva/…` |
| Марка и модель | `/cars/mercedes/s_klasse/…` |
| Год выпуска | `/2022-year/` |
| Цена до | `/do-3000000/` |
| Наличие | `/for-order/` |
| Кузов | `/body-sedan/` |
| Привод | `/drive-4x4_wheel/` |
| Коробка | `/transmission-automatic/` |
| Двигатель | `/engine-benzin/` |
| Цвет | `/color-belyj/` |
| Число мест, происхождение марки | `/seats-5/`, `/vendor-german/` |

Справочники значений:

| Параметр | Допустимые значения |
| --- | --- |
| `--category` | `cars`, `lcv`, `moto`, `trucks` |
| `--section` | `all`, `new`, `used` |
| `--availability` | `any`, `in_stock`, `order` |
| `--body` | `sedan`, `hatchback`, `hatchback_5_doors`, `hatchback_3_doors`, `wagon`, `liftback`, `coupe`, `cabrio`, `allroad`, `allroad_5_doors`, `allroad_3_doors`, `pickup`, `van`, `minivan` |
| `--drive` | `rear_wheel`, `forward_wheel`, `4x4_wheel` |
| `--transmission` | `mechanical`, `automatic`, `robot`, `variator` |
| `--engine` | `benzin`, `dizel`, `lpg`, `electro`, `gibrid`, `turbo` |
| `--origin` | `domestic`, `european`, `german`, `japanese`, `korean`, `chinese`, `american`, `foreign` |

Значения для `--mark`, `--model`, `--geo` и `--color` задаются слагом
без указания сайта; полный перечень доступен на странице фильтра.

**Фильтры, применяемые к собранным данным.** Сайт поддерживает их исключительно
через параметры в адресе, а подобные адреса запрещены правилами сайта:

| Фильтр | Способ применения |
| --- | --- |
| Пробег до N | локальный запрос к таблице |
| Тип продавца (частное лицо или дилер) | локальный запрос к таблице |
| Состояние (битый или нет) | локальный запрос к таблице |

Данные после сбора всё равно находятся в базе, поэтому указанные условия
выполняются точным локальным запросом без дополнительных обращений к сайту.
Ограничение относится к способу фильтрации, а не к возможностям инструмента.

## Правила обращения к сайту

Соблюдение `robots.txt` и отказ от обхода защитных механизмов сайта являются
частью архитектуры, а не вспомогательной мерой.

- Адреса с параметрами не запрашиваются, поскольку `robots.txt` их запрещает.
  Постраничный обход по этой причине отсутствует: выборка разделяется на более
  узкие фильтры, при которых каждый запрос укладывается в один ответ.
- Идентификация браузера не подменяется идентификацией поискового робота, хотя
  сайт возвращает таким роботам больше данных.
- Подписи внутренних запросов сайта не вычисляются, защита не обходится.
- Телеметрия просмотров не отправляется.
- Телефоны продавцов, чаты и сообщения не запрашиваются.
- Частота запросов ограничена: по умолчанию не более 0,5 запроса в секунду с
  разбросом задержек (параметр `--rps`). Дополнительно действует плановый лимит
  запросов на прогон (по умолчанию 100, параметр `--max-requests`), который
  программа не повышает самостоятельно.
- Суточный лимит запросов в текущей версии не реализован. Ограничение
  представляется достаточным на уровне одного прогона; сквозной учёт за день
  отнесён к направлениям развития.
- При появлении проверки «человек» сбор приостанавливается и ожидает вмешательства
  оператора. Автоматическое решение проверок не применяется.

## Установка

```
pip install -e .                    # сбор и выгрузка
pip install -e ".[ui]"              # дополнительно: экран в терминале
pip install -e ".[service]"         # дополнительно: HTTP-сервис
pip install -e ".[all]"             # дополнительно: оба компонента
```

Имя пакета при установке — `autoru-market-dataset`; команда запускается как
`autoru`. Обязательный набор включает пять пакетов: httpx, pydantic, duckdb,
typer, structlog. Экран и сервис вынесены в необязательные наборы, поскольку для сбора
и выгрузки они не требуются, а их зависимости увеличивают объём установки
примерно на 8 МБ.

При запуске `autoru tui` или `autoru serve` без соответствующего пакета команда
сообщает, какой пакет отсутствует, и завершается с кодом 7. Трассировка стека
не выводится.

## Эксплуатация

```
autoru crawl --mark bmw --model x5 --geo moskva   # сбор выборки
autoru crawl --mark bmw --model x5 --full         # сбор всей выборки
autoru url --mark bmw --model x5                  # адрес выборки, без загрузки
autoru count                                      # объёмы в базе
autoru summary                                    # сводка по накопленному
autoru by-year                                    # сводка цен по годам
autoru changes                                    # изменения цен
autoru prices <offer_id>                          # история цен объявления
autoru check-hash                                 # проверка гипотезы о хеше
autoru export --fmt parquet --out data/all.parquet
autoru tui                                        # экран в терминале
autoru serve                                      # HTTP-сервис
```

**Экран в терминале** (`autoru tui`) обеспечивает ввод фильтров, отображение
ходода выполнения и остановку сбора. Управление доступно с клавиатуры: `S` —
запуск, `X` — остановка, `Q` — выход.

**HTTP-сервис** (`autoru serve`) принимает локальный адрес соединения по
умолчанию. Одновременно выполняется один сбор: параллельные обходы не повышают
производительность и увеличивают вероятность срабатывания защиты сайта.

### Коды завершения

| Код | Значение |
| --- | --- |
| 0 | выполнено успешно |
| 1 | запрошенные сведения отсутствуют: истории цен у объявления нет либо изменений цен ещё не было |
| 2 | некорректные параметры фильтра, неизвестная таблица выгрузки, отмена сбора или превышение лимита запросов |
| 3 | сайт не отдал данные |
| 4 | разбор полученной страницы не удался |
| 5 | по заданному фильтру объявлений не найдено |
| 6 | сайт потребовал подтверждение запроса; требуется вмешательство оператора |
| 7 | не установлен пакет, необходимый для запуска команды |

Коды 1 и 5 соответствуют штатным исходам, а не отказам: пустой результат по
корректному фильтру означает, что по нему объявлений нет.

Страница `/docs` представляет собой интерфейс Swagger, формируемый FastAPI из
схемы OpenAPI и загружаемый из сети. Веб-файлы в репозитории отсутствуют. При
необходимости документирования без доступа в сеть страница может быть отключена
и заменена статической.

## HTTP-сервис

Сервис обеспечивает интеграцию с внешней системой управления парсерами:
постановку задачи, наблюдение за ходом выполнения, остановку и получение
собранных данных.

| Запрос | Назначение |
| --- | --- |
| `GET /health` | проверка работоспособности и количество прогонов |
| `POST /runs` | постановка сбора; немедленный ответ с идентификатором |
| `GET /runs` | перечень прогонов |
| `GET /runs/{run_id}` | состояние и ход выполнения прогона |
| `POST /runs/{run_id}/cancel` | остановка прогона |
| `GET /offers` | объявления с параметрами `limit`, `offset`, `mileage_to`, `price_to`, `mark` |
| `GET /offers/{offer_id}/prices` | история цен одного объявления |
| `GET /summary` | сводка по накопленным данным |
| `GET /changes` | изменения цен |
| `GET /check-hash` | согласованность хешей |

Состояния прогона: `pending`, `running`, `done`, `failed`, `cancelled`, `blocked`.
Состояние `blocked` означает, что сайт потребовал подтверждение запроса: сбор
приостановлен и ожидает оператора. Сведения о продавцах сервис не возвращает.

Сведения о прогонах хранятся в памяти процесса и не сохраняются при перезапуске.
Собранные данные размещаются в DuckDB и сохраняются.

## Архитектура

```
обнаружение → сбор → нормализация → хранение → выгрузка
   sitemap       httpx    плоско, без ПДн   DuckDB    CSV, JSON, NDJSON, Parquet
```

Конкретная площадка отделима от логики сбора. Ядро не содержит сведений об
auto.ru: для каждой площадки реализуется единый контракт из трёх операций —
получить объявления по выборке, получить одно объявление, сообщить о ходе
выполнения. На этом же контракте к системе подключаются иные парсеры.

Транспортные оболочки — командная строка, экран и HTTP-сервис — не содержат
логики сбора и обращаются к одному и тому же модулю `services.crawl`.

## Хранение

- Основной формат — Parquet; чтение и запись выполняются через DuckDB.
- Используются две таблицы: текущее состояние каждого объявления и история
  изменений.
- Повторный запуск сбора не создаёт дубликатов: состояние обновляется по ключу,
  а в историю включаются только фактические изменения.
- CSV, JSON и NDJSON предназначены для выгрузки, а не для хранения.
- Полный ответ сайта не сохраняется: это увеличивает объём и влечёт сохранение
  персональных данных.

## Ограничения

- Постраничный обход отсутствует ввиду запрета параметров в адресах; полнота
  выборки обеспечивается разделением на узкие фильтры.
- Разделение ограничено однородностью данных: при равных значениях фильтров
  дальнейшее сужение невозможно. Измеренная полнота зависит от марки и года:
  для X5 2023 года составляет 82 %, для 2021 года — 41 %, для 2019 года — 26 %.
- Суточный лимит запросов не реализован; действует лимит на один прогон.
- Фильтры «пробег», «тип продавца» и «состояние» применяются только к
  собранным данным.
- История цен накапливается по результатам последовательных сборов; в пределах
  одного дня цены не изменяются.
- Гипотеза о зависимости хеша от цены проверяется командой `autoru check-hash`;
  для получения ответа требуется накопление данных за несколько сборов.
- Авторизация на сайте не применяется и не предусмотрена: она не предоставила
  дополнительных полей, а с её cookies обычный клиент получает отказ.
- Сведения о прогонах в HTTP-сервисе не сохраняются между перезапусками.

## Направления развития

- Накопление истории цен в регулярном темпе.
- Проверка полноты выборки на нескольких марках.
- Развитие измерения полноты на однородных данных.
