# Changelog

Журнал изменений в формате Keep a Changelog. Нумерация версий выполняется по
дате до первого стабильного релиза.

Документ предназначен для публичного использования: сведения о внутренних
решениях, рабочих дневниках и вспомогательных материалах проекта в него не
включаются.

Порядок работы с журналом:

- запись вносится одновременно с изменением, а не по его завершении;
- фиксируются изменения, наблюдаемые пользователем: добавленные возможности,
  изменённое поведение, устранённые дефекты, необходимые миграции;
- внутренний рефакторинг, переименование функций, форматирование и комментарии
  не отражаются;
- изложение ведётся в прошедшем времени от лица пользователя.

## [2026-10-06] — версия 0.4.0

Реализованы экран в терминале и HTTP-сервис. Парсером можно управлять из
внешней системы.

### Добавлено

- Команда `autoru tui` — экран сбора в терминале: ввод фильтров, отображение
  хода выполнения, остановка сбора. Управление доступно с клавиатуры.
- Команда `autoru serve` — HTTP-сервис с постановкой сборов, наблюдением за
  прогрессом, остановкой и выдачей собранных данных. Соединение принимается на
  локальном адресе; схема API доступна на `/docs`.
- Состояния прогона в сервисе: `pending`, `running`, `done`, `failed`,
  `cancelled`, `blocked`. Состояние `blocked` означает, что сайт потребовал
  подтверждение запроса.
- Сопоставление состояния прогона с локальными и HTTP-средствами: при
  появлении проверки со стороны сайта выводится разъяснение о произошедшем и
  о требуемом действии.

### Изменено

- Экран и HTTP-сервис вынесены из обязательного набора зависимостей в
  необязательные наборы `ui`, `service`, `all`. Установка для целей сбора и
  выгрузки больше не требует Textual, FastAPI и Uvicorn.
- При запуске `autoru tui` или `autoru serve` без требуемого пакета выводится
  указание недостающего пакета и команды установки; процесс завершается с кодом
  7. Ранее выводилась трассировка стека.
- Одновременное выполнение сборов ограничено одним прогоном.

### Исправлено

- Досрочная остановка сбора больше не приводит к потере уже собранных данных.
- Тексты ошибок, содержащие квадратные скобки, больше не приводят к отказу
  экрана в терминале.
- Сетевые соединения освобождаются по завершении прогона.
- Повторное нажатие кнопки запуска сбора в экране в терминале больше не инициирует
  параллельный обход.

## [2026-10-06] — версия 0.3.0

Реализованы выгрузка данных и просмотр накопленной истории цен.

### Добавлено

- Команда `autoru export` — выгрузка в CSV, JSON, NDJSON или Parquet.
  Доступны текущие объявления и история изменений (`--table snapshots`).
- Локальные фильтры выгрузки: `--mileage-to`, `--mileage-from`, `--price-from`,
  `--price-to`, `--year-from`, `--year-to`, `--seller-type`, `--mark`.
- Команда `autoru summary` — объёмы, диапазон годов и цен, распределение объявлений
  между частными лицами и автосалонами.
- Команда `autoru prices` — история цен одного объявления с расчётом процента
  изменения.
- Команда `autoru changes` — изменения цен по всем объявлениям, актуальные записи
  первыми.
- Команда `autoru by-year` — средняя и медианная цена, количество автомобилей и
  средний пробег по годам выпуска.
- Команда `autoru check-hash` — проверка гипотезы о зависимости хеша от цены.

### Исправлено

- Устранено загрязнение истории служебными метками сайта. Метки появлялись и
  исчезали между прогонами, и каждое такое изменение создавало запись в истории
  при неизменных цене и пробеге. Три последовательных прогона добавляют ровно
  одну запись — только при фактическом изменении объявления.

### Ограничения

- Полнота выборки не изменилась: обеспечивается сбор до 37 объявлений, далее
  зависит от однородности данных.
- История цен остаётся пустой до накопления результатов сборов в разные дни.
  Гипотеза о хеше проверяется, ответа пока нет вследствие недостатка данных;
  команда сообщает об этом прямо.

## [2026-10-06] — версия 0.2.0

Реализован сбор выборки целиком без постраничного обхода.

### Добавлено

- Флаг `--full` команды `autoru crawl`: сбор всей выборки. Выборка
  разделяется по году, поколению, приводу, коробке и числу мест до достижения
  условия размещения каждой части на одной странице.
- Флаг `--max-depth` — глубина разбиения выборки.
- Вывод значения полноты: количество собранных объявлений, количество
  объявлений по данным сайта, число пустых частей.
- Явное указание причины невозможности собрать выборку целиком.

## [2026-10-06] — версия 0.1.0

Первая рабочая версия: объявления собираются и сохраняются в базу.

### Добавлено

- Команда `autoru url` — вывод адреса выборки по фильтру без загрузки данных.
  Позволяет проверить фильтр до сбора.
- Команда `autoru crawl` — сбор первой страницы выборки с записью объявлений в
  базу. Поддерживаются марка, модель, город или регион, год, цена до, наличие,
  кузов, цвет, привод, коробка, двигатель, число мест и происхождение марки.
- Команда `autoru count` — количество объявлений и записей истории в базе.
- Хранение в DuckDB: текущее состояние каждого объявления и история изменений.
  Повторный запуск не создаёт дубликатов; в историю включаются только фактические
  изменения.
- Собственная история цен. Сайт возвращает её частично, поэтому изменения цен
  накапливаются при ежедневных запусках.
- Извлечение из ответа сайта следующих сведений: марка, модель, поколение,
  модификация, двигатель, объём, мощность, время разгона, коробка, привод, кузов,
  год, пробег, количество владельцев, состояние ПТС и растаможки, количество
  фотографий, транспортный налог, признак «частное лицо или автосалон».

### Ограничения

- За один запуск выполняется сбор одной страницы, до 37 объявлений. Обеспечение
  полноты по расширенной выборке предусмотрено в последующих версиях.
- Фильтры «пробег», «тип продавца» и «состояние» сайт поддерживает только через
  параметры в адресе; такие адреса запрещены правилами сайта, поэтому фильтрация
  выполняется на собранных данных.
- Сведения о продавце не сохраняются: имя, телефон, адрес, город, название
  автосалона.

## Порядок нумерации версий

- Формат `0.Y.Z` применяется до первого публичного релиза; нумерация ведётся
  по дате.
- Формат `1.0.0` соответствует первой стабильной версии.
- Номер мажорной версии изменяется при нарушении совместимости: изменение формата
  файлов, изменение поведения по умолчанию, удаление функции.
- Минорная версия соответствует новым возможностям, патч — устранению дефектов
  без изменения поведения.
