# autoru-parser

Парсер объявлений [auto.ru](https://auto.ru/) для личного сбора датасета и
анализа рынка. Собирает характеристики и цены объявлений по заданным
фильтрам, хранит ежедневные снимки, чтобы было видно динамику.

**Статус: в разработке.** Работающей версии пока нет. Репозиторий содержит
проектирование и результаты технической разведки сайта; первый код ещё не
написан.

## Что это будет делать

- Собирать объявления по фильтрам: марка, модель, год, цена до, регион, кузов,
  привод, коробка, двигатель, цвет, «на заказ».
- Отдавать плоские таблицы: цена, пробег, год, марка, модель, кузов, двигатель,
  коробка, привод, цвет, количество фото, тип продавца, регион, состояние
  документов.
- Накапливать историю: ежедневные снимки, запись появляется только когда данные
  объявления действительно изменились.
- Не хранить ничего о продавце: ни имени, ни телефона, ни адреса, ни города.
- Работать и без веб-интерфейса, из командной строки.
- Подключаться к внешней системе управления парсерами по HTTP.

## Поддерживаемые фильтры

Фильтры разделены на две группы, и это важно понимать до начала использования.

**Работают на стороне сайта** — попадают в адрес как обычные части пути:

| Фильтр | Пример |
| --- | --- |
| Регион или город | `/moskva/…` |
| Марка и модель | `/cars/mercedes/s_klasse/…` |
| Год | `/2022-year/` |
| Цена до | `/do-3000000/` |
| На заказ | `/for-order/` |
| Кузов | `/body-sedan/` |
| Привод | `/drive-4x4_wheel/` |
| Коробка | `/transmission-automatic/` |
| Двигатель | `/engine-benzin/` |
| Цвет | `/color-belyj/` |
| Мест, происхождение марки | `/seats-5/`, `/vendor-german/` |

**Не поддерживаются на стороне сайта** — применяются к уже собранным данным:

| Фильтр | Почему |
| --- | --- |
| Пробег до N | Сайт умеет только через параметр в адресе, а такие адреса запрещены правилами сайта |
| Тип продавца (дилер или частник) | То же |
| Состояние (битый или нет) | То же |

Это не ограничение инструмента, а сознательный выбор: собранные данные всё
равно складываются в базу, поэтому пробег и тип продавца фильтруются обычным
запросом к таблице — точно и без лишних обращений к сайту.

## Правила обращения к сайту

Проект соблюдает `robots.txt` сайта и сознательно отказывается от обхода
защиты. Это не формальность, а часть архитектуры.

- Не запрашиваются адреса с параметрами — `robots.txt` их запрещает.
  Поэтому постраничного обхода нет: вместо него выборка делится более узкими
  фильтрами, и каждый запрос укладывается в один ответ.
- Не подменяется идентификация браузера под поискового робота, хотя сайт
  отдаёт таким роботам больше данных.
- Не вычисляются подписи внутренних запросов сайта и не обходится защита.
- Не отправляется телеметрия просмотров.
- Телефоны продавцов, чаты и сообщения не запрашиваются — там персональные
  данные.
- Темп ограничен: не более 0.5 запроса в секунду, с разбросом задержек и
  суточным лимитом.
- Если появляется проверка «человек» — сбор встаёт на паузу и ждёт человека.
  Никакого автоматического решения проверок.

## Как устроено

```
обнаружение → сбор → нормализация → хранение → экспорт
   sitemap    httpx    плоско, без PII    DuckDB      CSV, JSON
                          + Parquet
```

Подробное устройство — в документации проекта.

Парсер сделан так, чтобы конкретная площадка была отделима от логики сбора.
Ядро не знает, что такое auto.ru: для каждой площадки реализуется один и тот же
контракт из трёх операций — найти объявления, получить одно объявление,
отчитаться о прогрессе. На этом же контракте к системе смогут подключаться
другие парсеры.

## Хранение

- Основной формат — Parquet, читается и пишется через DuckDB.
- Две таблицы: текущее состояние каждого объявления и история изменений.
- Повторный запуск сбора не создаёт дублей: состояние обновляется по ключу,
  а в историю попадает только то, что изменилось.
- CSV и JSON — экспорт, а не основное хранилище.
- Сырой ответ сайта целиком не сохраняется: это раздувает объём и тянет внутрь
  личные данные.

## Технологии

Python, асинхронный HTTP-клиент, DuckDB и Parquet, Pydantic для схем данных,
Typer и Textual для командной строки, Playwright — только для ручного прохождения
проверок, и только опционально.

## Что дальше

Первые версии: вертикальный срез сбора одной модели в одном регионе, полнота
выборки через деление на узкие фильтры, история цен и экспорт. Затем — локальный
интерфейс и HTTP-сервис, чтобы парсером можно было управлять из общей системы.
